# Plan: VoxelCraft - Playable Minecraft-like

## Goal
Transform the current static voxel terrain viewer into a playable, first-person block game (inspired by Minecraft 0.8-alpha). Focus on: player movement with gravity/collision, block raycast/picking, block breaking/placing, and incremental chunk/tile re-meshing when blocks change.

## Phase 1 - Understand (done)
- Explored current codebase: `index.html`, `app.js` (1237 lines), `styles.css`, contributors, runtime scripts
- Explored mcp940 (Minecraft 1.12 MCP, Java) - rich algorithms for terrain gen, biomes, entities, etc.
- Explored minecraft-decompiled-0.8-alpha (Java) - minimal, readable: `LevelGen` (diamond-square+blobs), `Player`/`Entity`/`AABB`, `LevelRenderer` (dirty chunks, MAX_REBUILDS_PER_FRAME), `Level`/`Chunk`, picking/highlight
- Key gap: viewer only, no FP controls, no physics/collision, no edit/interaction

## Phase 2 - Design
We need to add a playable loop without breaking the existing procedural generator/UI.

### Architecture changes to app.js
1. **Player + Physics (AABB-based)**
- Add `Entity`/`Player` concepts in JS: position, velocity (x,y,z), size (AABB), onGround, look (yaw/pitch)
- Port `AABB` (intersect, offset, expand, contract or similar) from 0.8
- Collision detection: test against block AABBs in loaded region (we already have `colMap` for each column). A block is solid if it's not water and not a leaf block? Current: water is a block type present in `colMap` (when below water level we add water above terrain) and leaves are `leaves:*`. Treat `water` as non-solid for collision (or swim) and leaves as solid? Probably solid for walking.
- Gravity: apply vertical velocity, step movement (separately in axes) like 0.8
- First-person camera: use `THREE.PerspectiveCamera` (already used) attached to player head; pointer-lock via `PointerLockControls`-style approach, or implement yaw/pitch from mouse
- Input: WASD (move), Space (jump), Shift/Ctrl (optional), mouse look (pointer lock)

2. **Block Raycast/Picking**
- Ray from camera forward: intersect with blocks in view. 0.8 `Level.pick`/`HitResult` - find first solid block, return face/pos
- Highlight: add a wireframe/block-outline mesh (e.g. `THREE.BoxHelper` or small geometry) showing targeted block
- Break (left click), Place (right click). Need held block in hotbar.

3. **Hotbar / Block Selection**
- Add minimal UI in HTML: bottom bar with 8-10 slots showing block icons (can reuse tiny canvases from `buildTextures`)
- Default blocks: `grass`, `dirt`, `stone`, `sand`, `log`, `leavesOak`, `snow`
- Cycle with mouse wheel or numbers 1-9

4. **Editing World: colMap + dirty tiles**
- When breaking: remove that (y,typeId) from the column array (or find and splice). If it becomes empty of terrain above water? columns contain entries for every y from 0..h plus water if present - so just remove the specific y entry.
- When placing: if no entry exists for y at (x,z), insert in sorted order (columns are sorted ascending by y). Also need to be careful not to break water logic.
- After edit: mark the tile containing (x,z) as dirty. Rebuild only that tile mesh (we already have `buildTileMesh` returning a `THREE.Group`; we can dispose geometries/materials of the old group and replace it). The 0.8 approach: mark chunk as dirty, sort by distance from camera, rebuild up to `MAX_REBUILDS_PER_FRAME` (e.g. 1-4) to keep 60fps.
- Since we use TILE=64, a single 64x64 column set is small (max ~64x64x256 entries total per tile, trivial to rebuild).

5. **UI Additions (minimal)**
- In `index.html`: add `#crosshair`, `#hotbar`, `#block-info` elements; keep existing sidebar (optional to disable while playing, but fine)
- Pointer-lock: click on canvas to lock; ESC to unlock. Show instructions
- F3-like minimal: FPS, pos, looking-at block (optional but cheap)

6. **Rendering/loop changes**
- Extend `animate(dt)` to update player: input, velocity, collision, camera
- Track `lastTime` for dt
- Handle pointer lock state
- Per-frame: maybe rebuild one dirty tile if any
- Keep cloud drift and auto-rotate (disable auto-rotate when pointer-locked or moving? maybe fine)

### Files to modify
- `index.html`: add crosshair, hotbar, block info UI
- `styles.css`: styles for new UI
- `app.js`: add AABB, input, player, raycast, block editing, dirty tile tracking, pointer lock

## Phase 4 - Implementation Plan (step by step)
1. **UI scaffolding**
- Add HTML for crosshair (center dot), hotbar (row of slots), block info text
- Add CSS for these (fixed bottom/center)

2. **Input system**
- Track keys: `w,a,s,d,space,shift,ctrl`, mouse buttons, wheel
- Pointer lock API on `#cv`

3. **AABB class/objects**
- Functions: `aabb(x0,y0,z0,x1,y1,z1)`, `intersects(a,b)`, `move(a, dx,dy,dz, world, getBlock)` returning (a', dx,dy,dz, collided)
- For world test: check blocks the AABB intersects (integer coords from floor(min) to ceil(max))

4. **Player**
- `player = { pos:[cx, h+2, cz], vel:[0,0,0], yaw:Math.PI, pitch:0, size:[0.6,1.8,0.6], onGround:false }` (typical)
- `spawn()` after world gen: find ground height at center-ish

5. **Raycast**
- From eye (pos + [0, eyeY, 0], eyeY~1.6) in direction from yaw/pitch: step by small delta until hit solid block or max dist (e.g. 4.5)
- Return `{ hit:true, x,y,z, face, dist }`

6. **Editing**
- Left click: if hit, remove block at (x,y,z). Update `colMap` for that column.
- Right click: if hit, place on adjacent face at (nx,ny,nz) if empty and not intersecting player AABB
- Track `dirtyTiles = new Set()` of tile indices `tx/TILE + (tz/TILE)*(CHUNK/TILE)` or just (tileTx, tileTz)

7. **Tile management**
- Keep `tileGroups` map: key `tx+','+tz` -> { group, meshGroup }
- On edit: compute tile keys for affected columns and rebuild those groups (dispose old geometries: traverse and `geometry.dispose()`, materials handled by `matCache` reuse)
- Optionally throttle rebuilds to once per frame if multiple edits

8. **Loop integration**
- Add `keys = {}`, `mouse = { down:false, buttons:0 }`
- `update(dt)`: apply gravity (-16 m/s²), integrate velocity with collisions, update camera
- `render()`: renderer.render as before
- Rebuild dirty tiles adaptively (target >=1 per frame), respecting cfg.maxRebuildsPerFrame and frame time budget

9. **Hotbar**
- Render simple DOM: 9 slots, highlight selected, show texture thumbnails via `canvas.toDataURL` or just colored blocks? Easier: use small canvases or CSS backgrounds derived from existing textures (or generate 16x16 thumbs)
- Cycle on wheel: `selected = (selected+dir+count)%count`
