# Plan: Adapt the JSNES SEEK/PLAY agent to this app (configurable brain + debug HUD)

## 1. Verdict up front

Do NOT paste the `SnesSeekPlayAgent` class in — it targets the wrong
emulator. This app runs **EmulatorJS (Snes9x core)**, not JSNES:

| Pasted class assumes | This app actually uses |
|---|---|
| `nes.buttonDown(1, button)` / `buttonUp` | `window.EJS_emulator.gameManager.simulateInput(0, idx, 1/0)` (`script.js:221-229`, via `driveIndex`) |
| JSNES 8-button NES map (0=A,1=B,…,7=Right) | RetroArch 12-button SNES map (`PADINDEX`, `script.js:211`): B=0,Y=1,Select=2,Start=3,Up=4,Down=5,Left=6,Right=7,A=8,X=9,L=10,R=11 |
| Instant mode switch on one diff sample | Hysteresis (PLAY needs `d>8` ×2, SEEK needs `d<4` ×3, `script.js:364-370`) — deliberate, kills flicker |
| Fixed hold-Right in PLAY | Scroll-direction steering already exists (`colShift`, `script.js:502-514`, `autoDir`) |

The app's existing brain (`script.js:327-396`) is already a superset of the
pasted class (hysteresis, black-screen fast-path `355-359`, steering,
alternating A/B `329,379-383`, grab-to-take-over `262-264,301-302`,
single-instance, recorder integration via `driveIndex` src tagging).
So the job is a **port of the three asks** at the end of the pasted message,
adapted to our architecture:
1. ~~Scroll-direction detection~~ — already exists, keep.
2. **Visible debug HUD** (mode + diff value) — build.
3. **Configurable button mapping** (object) — build, plus a small options object.

## 5. Build deviations (executed)
- **Root-cause fix, vision was blind:** the EJS canvas is created with
  `preserveDrawingBuffer:false`, so 2D readback returned pure black —
  `d=0.0` forever, PLAY unreachable, recorder saving black frames. Added a
  `getContext` patch forcing `preserveDrawingBuffer:true` before the loader
  runs (verified: mean 0.0 → 128.6). Without this, the whole plan is dead.
- **SEEK taps generalized:** fixed `START-every-Nth` replaced by configurable
  `seekCycle` string (default `'2,2,3,8'` = SELECT, SELECT, START, A) after
  the file-select screen proved immune to SELECT/START (its SELECT flips
  controller TYPE; A confirms the file). Cycle is parsed/validated at engine
  start and editable in the modal. Tune grid therefore has 5 numbers + cycle
  text instead of 6 numbers.
- Verified end state: `PLAY · d=85.9 ▶` live, persistence round-trips,
  mobile clean, zero errors.
