# Plan: Full-Catalog 7-Stage Asset Pipeline + Unity Migration

## Goal
Run the **entire game catalog** (enemies imp/demon/baron, 5 guns, 6 wall sets +
floor/ceiling, pickups, barrels, projectiles) through a professional 7-stage art
pipeline — blockout → high-poly → procedural → retopo → UV → bake/texture →
rig/export — with **Unity as the final runtime**, built entirely with
**headless/in-repo tooling** (Python stdlib, Node + vendored three.js r160,
headless Chromium). Scaffold the full pipeline up front, then run the catalog.

## User decisions (locked)
1. Whole catalog at once (not per-asset pilot). 2. Unity runtime target.
3. Everything producible in-repo/headless — no Blender/Substance/Houdini; manual
external steps are NOT acceptable. 4. Full scaffolding up front, then the run.

## Ground truth (verified read-only)
- `game.js` (726 lines) + `levels.js` (12 ASCII levels) + `index.html` (importmap
→ `vendor/`) + `style.css`; deploy = manual copy to `dist/` served by `start.sh`;
verify = `node validate-levels.mjs` + `capture.sh` (playwright-cli, SwiftShader).
- Current art: 6 color-only 256px PNGs (`assets/tex/`), 5 Flat-Guns GLBs
(`assets/glb/`, ~1.3MB), 7 sfx, 48×56 canvas billboard enemies (no rigs/LODs),
`MeshStandardMaterial` w/ scalar roughness/metalness, merged `BoxGeometry`
walls (`WALL_H=2.4`), 2D-grid collision, `RoomEnvironment` IBL.
- No `vendor/addons/exporters/` — **GLTFExporter must be vendored first**.

## Layout (all additive; web game untouched)

- `pipeline/stages/s1..s7` + `pipeline/out/` (gitignored) + `pipeline/dist/`

- `unity/Assets/PlayGround/{Models,Textures,Materials,Prefabs,Scripts/...}` +

swizzle note). Web gains only an opt-in `?pbr=1` preview (default OFF).

## Per-stage headless method
1. **Blockout** (`s1_blockout.py`): parametric boxes/cylinders to game metrics
(tile 1×2.4×1, enemy 0.95×1.1 / demon ×1.28, barrel r0.28 h0.7, pickup
0.4×0.3×0.4); 1u=1m, Y-up → `block.obj` + `block.json`.
2. **High-poly "by construction"**: 1–2 Loop-ish midpoint subdivisions + analytic
normal displacement from procedural heightfields (brick mortar/hash, concrete
fbm, metal streaks+rivets, wood sine-warp, ridged rock, plaster fbm, gun
knurling grids, enemy muscle gaussians). No true sculpting — statistical detail.
3. **Procedural**: seeded stdlib value-noise/fbm (tileable lattice), 1024²
heightfields, params+seed logged to manifest. The Substance replacement.
4. **Retopo "cage by construction"**: Stage-1 cage subdivided once (≤ budget),
snap-to-high along normals (spatial hash), weld @1e-4, drop degenerates.
5. **UV analytic** (no unwrapper): box/planar per tile, per-part box-project
atlas for guns/props, cylindrical wrap for enemies; validate 0–1, no NaN,
coverage >85%, texel density in manifest.
6. **Bake CPU-only** @1024 (walls/enemies/guns) / 512 (props) / 256 emissive
(projectiles): `albedo` sRGB, `normal` linear OpenGL+ Y via Sobel of heightfield,
`orm` packed linear (R=AO, G=rough, B=metal). Ship `*_mask.png` pre-swizzled
for URP (R=metal G=AO A=smoothness) + document three-vs-Unity channel remap.
7. **Rig/export `.glb` only** (FBX infeasible in-repo): Node + vendored
GLTFExporter; enemies get 12-bone skeleton (baron 14: +pads+jaw) with coded
clips (walk 0.6s loop, hurt 0.15s, dead 0.22s, baron swipe 0.5s); statics
skinless; re-load via GLTFLoader headless to validate.

- Naming: `<cat>_<name>_low.glb`, `<cat>_<name>_{albedo,normal,orm,mask}.png`.

## Unity specifics
- Install `UnityGLTF` via Package Manager git URL for glB; URP 2022.3+ LTS,
Linear color space; copy `unity/Assets/PlayGround` in.
- Material map: Base(sRGB) / Normal(linear, Y-flip note) / MaskMap(swizzled) /
Emission; `envMapIntensity .35` → reflection probe slider; scale 1u=1m,
`WPNS` grip/flash vectors reused as meters; enemies Generic avatar (not
Humanoid); wall prefab BoxCollider (1,2.4,1).
- `SmokeTest.cs` (menu item, no Play mode): model count == catalog, tri counts,
material slots assigned, collider sizes, scale sanity → Console PASS/FAIL.
- Headless CAN validate: manifest, budgets (glB JSON parse), PNG headers,
glB reload, parity diff, levels, capture, C# text grep. CANNOT: Unity import
look, avatar limits, Play-mode — user runs SmokeTest + eyeballs.

## Validators & gates
`validate-assets.mjs`: manifest/naming conformance → budgets → map presence +
normal-blue check + ORM channel variance + tile seam delta <8 → headless glB
load (SwiftShader) → parity (wall Δ<0.25, enemy silhouette IoU>0.6, thresholds
in catalog) → regression (`validate-levels.mjs` ALL VALID + `capture.sh`
desktop/mobile >5KB). `validate-unity.mjs`: folder mapping + SmokeTest
content. Pipeline never writes `dist/`; promotion is explicit copy when green.

## Staging (web stays green throughout)
A. Scaffolding + vendor exporter + catalog + validator skeletons (web untouched).
B. Per-category runs → `pipeline/dist/` + `unity/` only (walls first for early
win); `?pbr=1` preview behind flag.
C. Unity folder + SmokeTest.cs + docs; user validates in Unity.
D. (Out of scope) gameplay port: ASCII→spawner, grid collision, WPNS, barrels,
particles; web stays canonical level-design source until Unity play-parity.

## Risks
- Statistical ≠ sculpted detail (enemies read stylized/blocky; keep billboard
fallback in web). Billboard→mesh changes facing/shadow/animator needs; parity
IoU may fail first pass — tune, don't hide. Sobel normals lack undercuts;
URP flatter than Substance. Pure-Python 1024² fbm ≈ minutes/asset — chunk,
cache, run per-category. Unity glB needs manual material/normal-flip/swizzle
steps — SmokeTest mandatory. Never attempt FBX writer.

## Effort order
Scaffold+exporter+catalog → shared libs → walls/floor/ceiling → props →
guns → enemies+rig → Unity folder+SmokeTest+docs (≈7–10 focused days).

## Verification (end-to-end)

## Phase E: PlayStation-style controls (twin-stick gamepad + console feel)
Goal: gamepad support with standard PS mapping, aim assist, sprint, ADS zoom,
hold-to-fire. Keyboard/mouse/touch unchanged (additive only). Files: `game.js`
(+ `dist/` mirror); maybe one hint line in `index.html` overlay.

Mapping (standard pad, `navigator.getGamepads()[first non-null]` polled in `move()`):
- Left stick (axes 0/1): move/strafe → feeds existing `fw`/`st`.
- Right stick (axes 2/3): look, deadzone 0.18 radial + expo curve,
  ~2.6 rad/s yaw at full deflection, pitch clamp ±1.2 (same as mouse).
- R2 (btn 7, analog >0.3): `firing=true` → `fire()` in `move()` if cd ready
  (also completes old hold-to-fire item; mouse `mousedown` sets same flag,
  `mouseup`/`blur` clears).
- L2 (btn 6, >0.3): ADS — lerp `camera.fov` 75→55 + look sens ×0.6.
- L3 (btn 10): sprint — move speed ×1.6 while held. (+ Shift key parity.)
- Triangle (btn 3, edge-trigger): cycle owned weapons. D-pad (btn 12–15,
  edge-trigger): direct select owned slots 1–4 (Up=cycle back? keep: L/R cycle,
  U/D = med/ammo status say? simplest: D-pad Up/Down/Left/Right → slots).
  Decide exact D-pad map at implementation; keep to weapon select.
- R3 (btn 11, edge): 180° quick-turn. Options (btn 9, edge): pause toggle /
  startPlay from overlay. Cross/Circle/Square: unbound (engine has no
  jump/crouch/reload) — documented, not silently mapped.
- Aim assist: nearest visible (`hasLOS`) foe within ~6° cone and 14u pulls yaw
  (magnetism ~40% of angular error per frame, only while right-stick active);
  small snap (≤2°) applied inside `fire()` when R2-fired. No assist for mouse.
- Rumble (optional): `GamepadHapticActuator.playEffect('dual-rumble')` on
  fire/hurt, guarded try/catch, skipped if unsupported.
- Edge triggers need prev-button state array; pad polling must no-op when no
  gamepad (zero behavior change), and gamepad look must not require pointer lock.
