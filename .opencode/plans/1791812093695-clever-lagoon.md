# Plan: Remove the fake GameBoy border

## Goal
Remove the fake GameBoy device shell (purple bezel, screen bezel, POWER label,
"GAME BOY COLOR" label, Nintendo branding, D-pad / A-B / Start-Select buttons,
speaker grille) so the game fills the viewport directly.

## What the "border" is (verified)
- `src/components/Gameboy.tsx` — the entire shell. Only the inner
  `<div className="display">{children}</div>` is the real game screen; every
  sibling (`.display-section` bezel, `.screen-area`, `.power`, `.label`,
  `.nintendo`, `.control-section`, `.speaker`) is chrome.
- `src/components/gameboy.css` (470 lines) — all shell styling, plus global
  `html/body` rules (`body { padding: 30px; ... }`) at the bottom.
- `src/App.tsx` — mounts `StyledApp > Gameboy > (Game, Paint)`.
- Nothing else references the shell: only `Gameboy.tsx` + `gameboy.css` use the
  class names (`display-section`, `control-section`, `screen-area`, `dpad`,
  `start-select`, `speaker`). `GameboyMenu`/`TitleScreen`/`LoadScreen` are
  in-game overlays *inside* `.display`, unaffected by name but need a new
  positioned ancestor (see below).

## Recommended approach: remove the wrapper, not CSS-hide it
Hiding via CSS leaves dead DOM/handlers and the `body { padding: 30px }`
conflict; clean removal is ~15 lines across 2 files.

### Changes
1. **`src/App.tsx`**
   - Drop `import Gameboy from "./components/Gameboy"`.
   - Render `<Game />` (and `{PAINT_MODE && <Paint />}`) inside a new fullscreen
     relative container that replaces what `.display` provided:
     ```tsx
     const StyledScreen = styled.div`
       position: relative;
       width: 100vw;
       height: 100dvh;
       overflow: hidden;
       background: black;
     `;
     ```
     This preserves the positioning/clipping context that `Game.tsx`
     (`Container`: absolute, 100%x100%) and the absolute overlays
     (`TitleScreen`, `LoadScreen`, `GameboyMenu`: absolute, 100%x100%,
     `z-index: 1000`) rely on.
   - Remove `padding: 5px; padding-bottom: 28px;` from `StyledApp` (was bezel
     compensation) so the game is truly edge-to-edge.
2. **`src/components/Gameboy.tsx` + `src/components/gameboy.css`**
   - Delete both files (removes the `import "./gameboy.css"` global `body`
     padding as well). Verify no other import of `gameboy.css` exists
     (exploration confirmed: none).
3. **No game-logic changes.** `Game.tsx`, overlays, `KeyboardHandler`, emitter,
   Redux slices stay untouched. Boot flow (GameboyMenu → Title → Load → map)
   works as before, just fullscreen.

### Known trade-offs (accepted)
- **Mobile touch controls disappear**: the on-screen D-pad/A/B/Start in
  `Gameboy.tsx` are the *only* touch input path (`onTouchStart/End` exist
  nowhere else). Desktop is fully playable via keyboard (Arrows = move,
  Enter = A, Shift = B, Space = Start; `Event.Select` has zero emitters or
  listeners, so nothing is lost). This matches the project's Desktop target.
  If touch is ever needed, add a minimal floating touch overlay as a
  follow-up (out of scope here).
- **Scale**: tile size derives from viewport width (`xToPx`/`yToPx` use
  `16vw/2.34`), so the map zooms to fill width automatically. Some
  `@media (max-width: 1000px)` font/padding rules assumed a tiny screen and
  may look oversized fullscreen — visual check in screenshots; fix only if
  visibly broken.
- `Paint.tsx` (`PAINT_MODE=false`, dev-only) is viewport-fixed and unaffected.
